# 1.0 release benchmark plan

Status: executing preparation. Tracking issue: https://github.com/basicmachines-co/basic-memory/issues/1828

## Objective and pinned targets

Compare released v0.24.1 with the 1.0 release candidate on main at
`0884e204d84ac9d18124ad78601a80925643f901`. Freeze this candidate for the first
comparison; later main changes require an explicitly labeled rerun. Record the
resolved baseline tag SHA before execution. Baseline resolved to
`1d0e09b6f4876c3f339c30e8dbfcf66e59e2c356`.

The primary question is whether agents complete equivalent memory tasks more
reliably and economically through the new tools. Also measure read/write load,
retrieval quality, startup and indexing independently.

## Fairness and execution

Use one benchmark harness revision for both products, with explicit rich/POSIX
v0.24.1 presets and a bm 1.0 preset. Never rename historical results. Compare
identical user goals and corpus bytes; surface-specific tool names and argument
contracts remain visible to the agent. Validate required tools against each
server's actual advertised schemas. Unsupported functionality is reported
separately, rather than silently removed from the denominator.

Isolate each product environment, config, database and corpus copy. Pin and
record product and harness SHAs, Python/dependency versions, model identifiers,
dataset checksums, schema order, prompts, budgets, truncation, and semantic/cache
settings. Use fresh task projects and deterministic grading wherever possible.
Keep all raw results and traces locally; publish only reviewed artifacts.

Start with LLM-free scripted plumbing tests. Follow with a small one-model pilot,
then the full agent matrix with at least three repeats per model and paired
confidence intervals. Pin models and any independent judge before hosted calls.
Performance claims require at least six alternating paired repetitions on an
otherwise idle host. Separate cold startup, warm operation and indexing time.

## Reproduce the scripted smoke

From `benchmarks/`, after installing the two pinned clones with `uv sync --frozen
--project .scratch/product-<version>`:

```bash
uv run bm-bench run agent-tasks --surfaces rich \
  --model scripted:benchmarks/datasets/agent-tasks/smoke-rich-script.json \
  --tasks curate-orphans --bm-local-path .scratch/product-v0.24.1 \
  --run-id release-smoke-rich-02 --strict --strict-surfaces
uv run bm-bench run agent-tasks --surfaces posix \
  --model scripted:benchmarks/datasets/agent-tasks/smoke-posix-script.json \
  --tasks curate-orphans --bm-local-path .scratch/product-v0.24.1 \
  --run-id release-smoke-posix-02 --strict --strict-surfaces
uv run bm-bench run agent-tasks --surfaces bm \
  --model scripted:benchmarks/datasets/agent-tasks/smoke-script.json \
  --tasks curate-orphans --bm-local-path .scratch/product-1.0-rc \
  --run-id release-smoke-bm-02 --strict --strict-surfaces
```

Use a new run ID for each rerun. Inspect `per-turn.jsonl` for tool errors as well
as the exit code: the canned answer can pass despite a failed tool dispatch.
