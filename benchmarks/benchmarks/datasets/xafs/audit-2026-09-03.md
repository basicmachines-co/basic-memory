## Dataset observations

**Question style.** The sample is dominated by exact-value extraction: license and confirmation IDs, dollar amounts, timestamps, docket numbers, and verbatim quotes. Six of 20 prompts ask for or are graded on a verbatim phrase (dp_001/q05, dp_001/q06, dp_003/q06, dp_005/q06, dp_005/q09; dp_004/q04(a)). All four dp_004 prompts embed relative file paths, and several others name the document type ("the SOW payment schedule table", "the HEART score component table", "the image transcription and the messages-with-super thread"). This favors systems that can open a named file and read it whole; it does not test recall of facts whose location is unknown. Multi-hop questions are two- or three-file cross-references where each hop is a direct lookup; no question in the sample requires aggregation, counting, or reasoning beyond matching two named values.

**Distractor density.** The corpus is deliberately seeded with near-duplicate and conflicting values, and the density is high. Examples touched by this sample: Karras HIC #1374829 vs Bremer HIC #0892461; SOW EoW8 payment June 12 vs engagement plan June 19; BBB filing 2026-01-30 vs "on or about 2026-02-04"; change-order date 2025-12-18 (five files) vs 2026-01-04 (case overview only); HEART "Sum (computed) 8" vs "documented 7"; peanut allergy "Anaphylactic" vs "Not a dramatic allergy"; Quentin "7 months in" vs "~18 months"; Smeg bought at Williams-Sonoma "Industry City" vs "Brookfield Place"; plumber "B&K Plumbing" vs "Liberty Plumbing" vs "Tony"; failed part "cracked copper at shutoff valve" vs "rusted hose clamp". Some of these are the intended target of a question (dp_004/q06). Others leak into questions that did not intend them (dp_004/q05, dp_005/q04, dp_003/q08), which is where the gold answers needed correction.

**Vendor-tilt signals (observed, not proven).** (1) Every persona has a `memory/` folder whose files pre-summarize the rest of the corpus (`memory/companies/coppertide-overview.md`, `memory/cases/park-v-karras-case-overview.md`, `memory/profiles/...`); 5 of 20 questions list a `memory/` file as gold. A system that indexes or privileges such summaries gets a head start, and the folder name matches the vendor's product concept. (2) Prompts that embed exact file paths and timestamps reward path/grep-style access. (3) Gold answers frequently reproduce a single source line, so chunk-granular retrieval that returns that line is rewarded over synthesis. (4) Two prompts carry false or loose premises that align with a wrong-but-present value in the corpus (dp_004/q05 "early 2026"; dp_005/q09 "the following week"). None of this shows intent, and I found no gold answer that depends on information outside the corpus.

**Gold quality.** All 20 gold answers contain the correct core value(s); no gold is contradicted by its source on the primary fact. The four corrections are for over-specification or unsupported additions (a total the prompt did not ask for, a time of day that conflicts with a second gold file, an interpretive gloss) and for one prompt premise that conflicts with the corpus. That is a good hit rate for a vendor-authored set, but the failure mode matters for this judge: extra gold clauses that a faithful answer will not reproduce turn correct answers into false negatives under "every part must match".

**Overall read.** The sample supports using xAFS as a SECONDARY dataset, with the four corrections applied and with these caveats stated alongside any aggregate number: (a) the task is closer to file-and-line lookup than to memory recall, so scores will track raw-file access and exact-string handling more than semantic retrieval quality; (b) verbatim-quote and ID-string items make the judge's exact-match behavior a large part of the score; (c) the planted-inconsistency design means a system that reads more of the corpus can be penalized for surfacing a conflicting value that is also in the corpus (dp_005/q04(c), dp_004/q05(a)). Treat differences of a few points between systems as within noise on this set.
