# 1.0 RC tool comparison: first Haiku pilot

The three shared task goals passed on both versions. Across this small pilot,
the 1.0 catalog used **57.5% fewer agent tokens** and **three tool calls versus
five**. Treat this as pilot evidence; repeated runs and broader task/model
coverage remain necessary for a release recommendation.

| Task goal | v0.24.1 tokens | 1.0 RC tokens | v0.24.1 calls | 1.0 RC calls |
| --- | ---: | ---: | ---: | ---: |
| List one folder | 44,294 | 22,575 | 1 | 1 |
| Read by title | 42,534 | 20,801 | 1 | 1 |
| Write at an exact path | 65,014 | 21,108 | 3 | 1 |
| Total | 151,842 | 64,484 | 5 | 3 |

Tokens per completed task: **50,614 → 21,494.7**. Counts include all reported
agent input/output tokens. All tool calls conformed to their advertised schemas;
there were no tool errors or model/harness errors in these funded runs.

The legacy write used `write_note`, `move_note`, then `read_note`. The 1.0 write
used `bm_write`. Both produced the required file, frontmatter and observation,
preserving existing notes. The legacy write stopped on the token budget before
a final assistant reply; its file-state goal still passed. The 60,000-token
budget is checked before each model call, so a call can overshoot it (65,014
tokens here). The other five tasks ended with final replies. The new read/list
graders require a successful matching tool call as well as the correct answer.

## Reproducibility

- Baseline: v0.24.1, `1d0e09b6f4876c3f339c30e8dbfcf66e59e2c356`.
- Candidate: main/1.0 RC, `0884e204d84ac9d18124ad78601a80925643f901`.
- Harness: `9e4d2beb550b7741882946a18967e1b2db8bf072`.
- Model requested and returned: `claude-haiku-5-5`, Anthropic's OpenAI-compatible endpoint.
- Temperature omitted; eight turns and 60,000 pre-call tokens per task; 180-second task budget.
- Full catalogs: 27 legacy tools versus 12 bm tools, alphabetical schema order.
- Fresh isolated project/corpus per task, same prompts and deterministic graders.
- Product-default semantic settings on both products; SQLite; no Redis configuration.
- Corpus: 25 notes, SHA-256 `b91f5fe80849e2774b860b0b4a59d678eff2820201029570ed716fac9df12884`.
- Task specs: SHA-256 `985923496748505e8f3246aaf320343031fc922cd7ade07f1e3e9da68510ed28`.

Raw manifests include every tool schema/description supplied to the model.

error information. Supplementary `product-runtime.json` files record target
Python, installed package versions and lock hashes; both products use Python
3.14.8. `pilot-input.py` retains the local runner without credentials.

## Scripted mutation verification

All **20** real-MCP mutation checks passed: ten goals on each product. They cover
append, prepend, exact replacement, section replacement, before/after-section
insertion, metadata-only change, move, delete and stale-checksum refusal.
Each expected mutation was checked against the resulting files; unrelated notes
remained byte-identical. Body comparisons preserve exact nonblank lines in
order and ignore blank-line layout. Both stale-checksum calls produced an
actual conflict refusal and left all note bytes unchanged.

These are plumbing/correctness checks using scripted inputs, with embeddings
explicitly disabled. Their canned answers and fake token counts are excluded
from the real-model token comparison above. Artifacts:

- `benchmarks/benchmarks/runs/release-mutation-legacy-01/`
- `benchmarks/benchmarks/runs/release-mutation-bm-01/`
